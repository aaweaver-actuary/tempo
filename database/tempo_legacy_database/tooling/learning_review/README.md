# Learning review legacy database tooling

[run_postgres.py](run_postgres.py) retains the legacy-adapter review proofs' invocation-owned PostgreSQL harness. From a full repository checkout and the installed Learning/legacy test environment, optionally pass one evidence directory. The runner still rejects external targets and selection flags, verifies resource ownership before cleanup, and publishes success only after exact collection/execution/JUnit receipts and cleanup. The [native proofs](../../tests/learning_review/test_postgres.py) use the existing legacy adapters and roles; this is unchanged legacy coupling, not a new isolated database contract.

Only path/import wiring moved. Migrations, transaction boundaries, fixture SQL, resource limits and cleanup guards are unchanged. The ordinary [qualification workflow and inventory policy](../../../../services/learning/application/qualification.py) stay outside `database/`. These tooling/tests are source-distribution inputs only and do not enter the application runtime wheel. Checks for this relocation are offline packaging, source equivalence and [mocked lifecycle proofs](../../tests/learning_review/test_native_runner.py); native provisioning and database behavior were not executed.

The scoped guard run selected 100 existing cases: 93 passed and seven native mock cases failed because their unchanged Docker fake lacks the runner's existing resource-cap inspection response. The same seven failures were reproduced against the captured originals. This limitation remains open; no native qualification is claimed.
