# Legacy chess feature and statistics storage

**Current unmerged source; live schema/deployment unverified.** [storage.py](storage.py) owns complete existing projections, aggregate/dimension SQL, snapshot/insight writes and daily-job operations extracted from [statistics.py](../../../../backend/app/services/statistics.py). All operations borrow existing connections and never open, commit or close one. The existing canonical [feature writer](../games/derivation/features.py) and [claim-control SQL](../controls/claim_sql.py) are reused; there is no second feature writer, claim authority or generic execution interface.

```mermaid
flowchart LR
  application[Existing statistics composition] -->|borrowed source and aggregate reads| projections[Root statistics projections]
  application -->|existing chess, dates and metrics| calculations[Application algorithms and responses]
  calculations -->|same feature tuple| feature[Canonical feature-row writer]
  application -->|existing transaction and claim decisions| jobs[Root daily-job operations]
  application -->|selected snapshot and insight facts| publication[Root snapshot and insight writes]
```

The linked schema READMEs remain canonical for every stored type, primary/composite key, enforced FK and explicitly logical relationship. Complete daily JSON stores day/status, game count, nullable score and tactical counts; waiting JSON stores missing provider watermarks and blocked game IDs. Insights store that same accepted snapshot as evidence. The existing source DDL distinguishes stored backing tables from current-publication views. No schema, stored representation, owner permissions or Study dependency changes are introduced, and no live schema/data was inspected.

All 22 original database call sites are delegated: 21 fixed operations here plus the reused canonical feature writer. The fixed breakdown reader captures its whitelisted projection once, before invalid-dimension rejection, cutoff clock and connection entry; later mutation of the compatibility dictionary does not change the selected projection. SQL filter assembly executes inside the same bounded read scope. All chess/date/window/metric/presentation algorithms, connection/admission lifecycles, callback order and job decisions remain in the legacy application file. This preserves existing coupling rather than claiming a new isolated runtime.

Focused checks cover existing exact denominators, timezone/DST, player-perspective evaluations, readiness and late-arrival invalidation, plus dimension rejection and projection capture before clock/connection, current-comparison filtering, pause/promotion/Study-mode job selection and the local SQL boundary. A one-time source comparison checks query/method/parameter expressions and unchanged application algorithms. Only fakes and task-owned SQLite ran; native PostgreSQL execution/locking, deployment/resource isolation and full-system behavior remain unverified. The [unfinished extraction inventory](../../../INVENTORY.md) tracks the remaining mixed files.
