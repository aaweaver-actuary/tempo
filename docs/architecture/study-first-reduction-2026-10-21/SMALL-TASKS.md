# Contract for a small implementation task

Use for any bounded Tempo assignment, not only the historical #357 programme. [Root working rules](../../../AGENTS.md) and [SPEC](../../../SPEC.md) govern scope. Parent issues coordinate; they are not whole-agent assignments.

## Start with a bounded input packet

Read the assignment and its named owner files. Derive outcome, exclusions, worker/delivery ownership, write boundary, acceptance, and stop condition from existing information. Do not create another planning document or preload historical inventories and PRs. Confirm the relevant published dependency and current source; an existing implementation or test may already satisfy the task.

## Status meanings

READY means the bounded task has usable prerequisites. BLOCKED names the missing contract, authority, or dependency. EXISTING PR / REVIEW means continue the established work rather than create a duplicate. HOST and EXPERT identify the particular external observation or authority decision needed; they do not block independent safe work.

A model-capability label is routing advice, not permission to weaken safeguards or a universal requirement for another reviewer.

## Keep implementation mechanical where possible

One assignment has one bounded result and agreed writable scope. Preserve supported behavior except the explicitly assigned change. Do not improve adjacent code, invent frameworks, or implement another owner's dependency.

For a blocker, return the missing fact/function/file, smallest safe alternative, tradeoff, and next owner. Supply a failing fixture when it meaningfully demonstrates an executable defect; a missing permission or product decision does not require a fabricated test.

## Verification ladder

This is selection by responsibility, not a ladder every worker must climb. Apply [test selection](../../../docs/testing.md#select-the-smallest-relevant-proof): component workers prove their changed behavior; native checks prove relevant infrastructure semantics; the delivery owner proves changed assembly; an authorized operator owns installation and any required genuine-data/device acceptance.

Reuse valid evidence. Distinguish environment failures from product failures. Do not reinstall unrelated stacks, retry without a changed condition or diagnostic hypothesis, or treat source/build success as deployment proof.

## Minimal handoff

Use the existing task/PR and the five [handoff statuses](../../../CONTRIBUTING.md#handoff). Link relevant commands/results rather than reproduce an evidence inventory. Record a tested/published revision difference when material. No new report file, universal global-diagnostic comparison, or new hashes/receipts framework is required.

Complete task-owned cleanup safely. No merge, deployment, live-state mutation, source/data destruction, or permission change follows from a component assignment without the corresponding authorization.
