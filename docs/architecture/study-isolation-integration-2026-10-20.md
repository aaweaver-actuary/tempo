## Structural result

Study reuses the training implementation through a physical entry that excludes
the named optional legacy implementations from its produced module graph and
offline inventory. The full local/demo composition owns optional views,
dialogs and their handoff state. Its bounded legacy seam is not a claim that
every legacy feature is independently substitutable. The named build guard is
not exhaustive proof against future renamed implementations.

The combined Learning lifespan retains both repairs: memory-only activity close,
non-waiting optional endgame close, then foreground database close. The optional
daemon retains its phase/transaction and closes its own pools after actual
completion. A caller timeout or cancellation is not a rollback assertion; an
unconfirmed write returns its operation identity for canonical receipt recovery.

Review policy reads through the borrowed command transaction. The queue owner
owns complete parameter-bound projection queries and refresh marks. Existing
first-issuance authority and daily-task → remediation → projection lock ordering
remain intact; no second writer, independent commit or producer queue dependency
was introduced.

## Limits and deployment prerequisites

- No deployment, live database mutation, Study restart, Games activation or CI
  enablement occurred in this repair/integration cycle. PR319 remains paused.
- Expected HostActivity workspace sources must be configured for missing/startup
  fail-closed protection. The default empty list permits absent sources.
- Asynchronous publication is bounded-memory accounting, not hard real-time
  exclusion. A new essential request can overlap an old published idle lease
  for up to 15 seconds; this tradeoff remains explicit.
- Optional endgame connection capacity must be included in deployment budgets:
  maximum `2 * foreground pool size + 3`, including maintenance and two optional
  size-one pools. Caller wait expiry does not terminate the owned database phase.
- Effective host/container limits and shared PostgreSQL/host contention must be
  checked before rollout. Source separation and disposable tests do not prove
  zero contention or independent infrastructure failure.
- Canonical diagram links/anchors and whitespace were checked. Exact GitHub
  Mermaid rendering/layout was not independently qualified.
