## Finding and authority contract

**No confirmed continuation-authority defect was demonstrated under the agreed provisional-authority contract.** The new regressions pass against unchanged PR production code. Meaningful coverage gaps were the actual frontend acquisition path observing successor invalidation, backend issuance refusal followed by replay, omitted-hint replay, and independent mutation refusal after successful issuance.

A committed review and its original response stay immutable. A validly issued continuation may be used provisionally while the browser has not observed invalidation. Once a successfully acquired authoritative queue changes/removes the successor identity, local activation must decline. Subsequent backend commands independently validate their own authority. **There is no guarantee against server-side invalidation that has not reached the browser.** A delayed original response or exact replay can still contain a successor subsequently invalidated on the server; that is historical evidence of issuance, not proof of current availability.

The server projection counter is not an issuance token. It is returned in queue payloads but is neither captured in `PreparedNextIdentity` nor compared by frontend activation. A newer publication can retain the same issued identity. The literal stronger claim that every counter increase revokes every prior continuation is **not implemented or proven**; a newer authoritative response can itself return and authorize the same successor, but that is distinct from fencing the historical continuation by its issuance generation. The absence of a numeric fence is a limitation, not by itself a demonstrated activation of an unauthorized successor. No extra per-review network request or generation schema change was justified by this audit.

## Regression additions and reproductions

- `pr229_observed_authoritative_invalidation_blocks_delayed_continuation` (6 cases): freeze A's review response; acquire an authoritative replacement/removal/order/day snapshot while retaining A's attempt; release the original accepted A→B receipt. Acceptance clears the outbox, but B does not activate.
- `pr229_new_publication_retaining_authorized_successor_preserves_continuation`: a new ready publication returning B as head keeps the matching continuation usable.
- `test_pr229_invalidated_successor_declines_without_duplicate_review` (6 cases): remove B's queue row or change its actual revision/cycle, pending-validation flag, superseding card or blocked status before A's command. A saves without issuing B; exact replay remains one review/receipt.
- `test_pr229_no_hint_receipt_cannot_acquire_continuation_on_replay`: save A without a hint, replay exactly, attempt to add B to the logical receipt's original envelope, and replay exactly again. The changed envelope conflicts; B is never issued.
- `test_pr229_historical_continuation_does_not_authorize_invalidated_mutation` (5 cases): save A→B, then archive/revise/bury/block-validation/delete B. Replay A unchanged; B's failure marker and review commands reject. A's receipt bytes and review remain unchanged.

No new regression demonstrated a failing production baseline. The first frontend test attempt used an incomplete projection fixture; schema validation correctly rejected it. Adding the required response fields fixed the fixture without production changes. Tests were never disabled to obtain passing evidence.

A physically removed projection is not always authority revocation: a previously completed, unchanged admitted attempt may still save from its durable origin. Existing recovery tests explicitly require this. Similarly, [retained issuance after promotion](https://github.com/aaweaver-actuary/tempo/blob/ef26a6d9c19969baa3f1b1974dd58bcb27a66032/backend/tests/test_queue_attempt_issuance.py#L84) establishes that an already issued identity can remain operable after promotion. Neither case authorizes an unrelated unissued successor.
