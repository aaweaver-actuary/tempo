# Authored Studies

Baseline: `9a7fc958356dd341c014d4feb677bd64227803e6`. The pre-feature PGN importer flattened variations into repertoire lines and omitted zero-move roots. Cards required a repertoire ID; the queue response joined repertoires, and the phone journal retained only an opening review grade. The focused baseline study-durability and phone-training suites passed 12 tests before these changes.

## Use the feature

Open **Studies** in local Tempo. Create a study and chapters, paste or upload PGN, inspect the preview, and commit selected records. A root with no moves remains a position. Source comments, variations, NAGs, arrows, squares, headers, and raw PGN are stored; malformed records remain inspectable with diagnostics. Select a position to author square, move/line, knight-route, choice, or explanation exercises. Practice does not schedule. **Enroll** admits only that exercise to the daily queue, within the separate new-study allowance. **Train now** explicitly adds an enrolled exercise outside the automatic introduction allowance.

Study exercises use stable UUIDs. A position occurrence belongs to one source record and tree; equal FENs in different sources are separate. A scheduled card belongs to one exercise, and several exercises can share a position. Teaching links are explicit `illustrates`, `contrasts`, or `follow_up` references, not chess moves. The same exercise linked more than once retains one active schedule.

## Persistence and revisions

`studies`, `study_chapters`, `study_sources`, `study_positions`, `study_exercises`, `study_exercise_revisions`, `study_links`, `study_attempts`, and `study_sibling_burials` hold authored material and evidence. The `cards` migration permits either legacy repertoire ownership or study-exercise ownership. It retains legacy IDs, reviews, FSRS fields, queue rows, indexes, and foreign keys. Before the one-time card-table rebuild, Tempo writes `tempo.db.before-studies-v1.bak` with SQLite's online backup API. Initialization is idempotent and checks foreign keys before committing. If migration fails, stop Tempo, retain the failed database for inspection, and restore the verified backup while the API is stopped, following `docs/STORAGE.md`; no downgrade is promised.

Every exercise edit creates an immutable revision. Explanations and further analysis are cosmetic and retain scheduling. Prompt, hint, interaction, or rubric changes are assessment-affecting. The editor defaults to **Reset schedule**: archive the former card and create a new card while retaining its reviews and attempts. **Preserve schedule** is explicit. Stale in-flight answers receive a conflict and never grade under a new rubric. Archiving content preserves history.

An attempt records its actual response, revision, method, assistance exposure, timestamps, assessment, and result. One SQLite transaction validates the queued card, exercise, revision, entry and cycle, then saves the attempt, FSRS review, and queue completion. Repeating an attempt ID with the same payload returns its original result; a changed payload or another attempt for a completed entry conflicts. Invalid and unrecognized submissions never become an automatic FSRS failure. Hints or solution exposure before commitment force guided scheduling. Post-answer feedback does not.

The first committed attempt is available separately from later reviews. Book points are optional; absent values remain unknown. Reviewing an exercise buries other exercises on the same position occurrence, plus any exercises sharing an authored sibling group, for the current local study day without changing FSRS due dates. Practice remains an explicit override and does not alter memory scheduling.

## Import, export, and grading

PGN preview is limited to 2 MB, 300 records, 20,000 nodes, depth 80, and variation depth 16. A parser diagnostic blocks authoring from that source. Exact reimport into the same chapter and source context is idempotent. Changed external PGN requires an explicit append or source update; an update stores a new source-tree version and retains older occurrences and local rubrics. **Import as a copy** creates new identities. A `.tempo-study.json` bundle has major schema version 1 and preserves content IDs, trees, revisions, and links. It excludes cards, reviews, attempts, and personal schedule. Ordinary PGN export warns that it loses Tempo questions and relationships. Full SQLite backup includes both study content and personal history.

Move/line reference recall grades only authored accepted UCI lines. Open chess judgment returns `unrecognized` for an unlisted legal move and offers labeled self-assessment after reveal. Square answers use `required ⊆ selected ⊆ required ∪ optional`; omitted and extra squares are distinct. Knight paths are ordered, at most three hops, and use static non-capturing geometry: other pieces remain fixed, the knight vacates its start, and the final square attacks every stated target. The same bounded search verifies negative answers. Choice answers use stable option IDs. Explanation answers require explicit commitment before rubric reveal and a Correct/Again self-assessment. No engine or LLM grades these authored answers.

Prepared phone queues carry a versioned rubric snapshot. The browser grades supported study responses locally and journals the actual answer, not merely a grade. Replay sends that response to Python for validation against the pinned revision, then applies one existing scheduling transaction. Another-device reviews and stale revisions remain visible as conflicts. Unknown schema or grader versions are unavailable offline. The phone never creates tomorrow's queue; defensive exercises still require the computer.

Book imports are private. Tempo does not fetch URLs found in PGN, and the public demo is not a private study store. Only original synthetic positions belong in tests and screenshots.
