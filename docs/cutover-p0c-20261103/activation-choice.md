A 7,258-definition fixture was generated from the existing deterministic `content_bundle` helper and passed the actual v2 validator: 7,802,643 normalized and canonical stage bytes, 184,500,224-byte process peak RSS, 1.403 s generation and 1.428 s validation on macOS Python 3.13.5. Each definition has exactly one one-move route/binding and fact; this is deliberately not a largest-real-graph or native activation proof. `probe.py` reproduces the case. A second count-bound run at 10,000 definitions/facts/routes/bindings validated with 10,751,453 canonical bytes, 217,563,136-byte peak RSS, 2.016 s generation and 1.989 s validation. Peak RSS includes imports, generation and validation; timings are one run each.

Content card IDs encode workspace/source/exercise identity; legacy opening IDs historically derive from FEN/moves. V2 accepts authored IDs and explicit one-to-one legacy aliases; adoption requires an existing compatible physical object and preserves that ID. The alias cap alone can reject 9,526 distinct required historical aliases, even though 9,526 historical cards cannot be assumed to require that many aliases. Preserve original review/attempt/position links and block on unknown mapping; current alias checks alone do not prove complete historical migration. The existing F12 native activation, stale source/partial staging and retained-history crosswalk remain unproven here. T00 prompt/ownership files were available but no separately pinned count/crosswalk output was identified; W01 must resolve mapping using actual captured source facts.

Historical #718 measured 2,207 lines, 9,526 cards and memberships, 27,600 graph rows and 17.78 MB of legacy snapshot wire data under a 384 MiB PostgreSQL ceiling; this is a different serializer, unit and historical SHA. It establishes neither v2 fit nor failure. No live data, DB, provider, installation or activation was accessed.
